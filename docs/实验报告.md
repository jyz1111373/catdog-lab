# 实验报告：猫狗图像分类 —— 从零搭建模型到部署上线

- **课程**：Hadoop 大数据技术（深度学习实验）
- **数据集**：100 张图片，猫 50 张 / 狗 50 张，标签由文件名给出（`cat.x.jpg` → 0，`dog.x.jpg` → 1）
- **划分**：分层抽样，80 张训练 / 20 张验证，随机种子固定 `seed=42`
- **环境**：Python 3.13 · torch 2.14.1+cpu · torchvision 0.29.1+cpu · scikit-learn 1.9.1 · CPU 训练

---

## 一、实验目的

1. 手写卷积神经网络（AlexNet），理解卷积 / 池化 / 全连接各层的作用；
2. 掌握"训练 → 验证 → 计算评价指标"的完整流程；
3. 用**控制变量法**对比三个技巧的实际收益：ImageNet 预训练、数据增强、模型选型；
4. 把训练好的模型封装成**可用的前后端应用**，让模型真正跑起来。

---

## 二、实验原理

| 概念 | 作用 |
|---|---|
| 卷积层 Conv2d | 用 3×3 / 5×5 / 11×11 的小窗口在图片上滑动，提取边缘、纹理、部件等局部特征 |
| 池化层 MaxPool2d | 把特征图缩小一半，保留最显著响应，同时扩大感受野 |
| BatchNorm | 把每层输入拉回稳定分布，让训练更快更稳 |
| 残差连接（ResNet 的 "+x"） | 让梯度可以"抄近道"传回浅层，网络再深也训得动 |
| 全连接层 Linear | 把卷积提取的特征图"汇总投票"，输出每个类别的得分 |
| 迁移学习 | ImageNet 预训练模型已学会通用视觉特征（边缘→纹理→部件→物体），小数据集上直接复用 |
| 数据增强 | 在不增加真实图片的前提下人为造出"看起来不同"的样本，逼模型学本质特征而不是背图 |

评价指标（macro 平均，验证集 20 张）：

$$\text{Accuracy}=\frac{TP+TN}{N},\quad P=\frac{TP}{TP+FP},\quad R=\frac{TP}{TP+FN},\quad F1=\frac{2PR}{P+R}$$

---

## 三、实验步骤与结果

> 所有实验共用同一份划分与同一套指标，每次只改一个变量，因此横向可比。

### 第一步：手写 AlexNet，从零训练（基线）

`scripts/step1_scratch.py` · 30 轮 · lr=1e-4 · Xavier 初始化

| 准确率 | 精确率 | 召回率 | F1 | AUC | 耗时 |
|---|---|---|---|---|---|
| 0.8500 | 0.8535 | 0.8500 | 0.8496 | 0.8000 | 71.6 s |

**讨论**：从零训练 30 轮能到 0.85，说明 80 张训练图并非完全学不动，
但代价是 71.6 秒的训练时间和明显更大的波动。这个数字是后面所有改进的参照系。

### 第二步：加载 ImageNet 预训练权重（迁移学习）

`scripts/step2_pretrained.py --finetune` · 5 轮

| 做法 | 准确率 | 精确率 | 召回率 | F1 | AUC | 耗时 |
|---|---|---|---|---|---|---|
| 冻结卷积层，只训分类头 | **0.9500** | 0.9545 | 0.9500 | 0.9499 | 1.0000 | 10.0 s |
| 解冻全部层微调（lr=1e-5） | 0.9000 | 0.9000 | 0.9000 | 0.9000 | 0.9400 | 13.2 s |

**讨论**：
- 灌入预训练权重后，准确率从 0.85 提到 **0.95**，训练时间反而从 71.6 s 降到 10 s——
  因为只训练最后一层，参数量大幅减少。
- 全量微调反而降了 5 个百分点：数据量太少，1e-5 的学习率也足以让已经很好的通用特征被"带偏"，
  是典型的**小数据过拟合**。
- 结论：**小数据集上，"知识从哪来"比"训练多久"重要得多。**

### 第三步：数据增强三组对照

`scripts/step3_augmentation.py` · 10 轮 · 同一模型 resnet18

| 组别 | 准确率 | 精确率 | 召回率 | F1 | 耗时 |
|---|---|---|---|---|---|
| 3a 从零训练 + 无增强 | 0.7500 | 0.7747 | 0.7500 | 0.7442 | 29.4 s |
| 3b 从零训练 + 有增强 | 0.8000 | 0.8000 | 0.8000 | 0.8000 | 32.4 s |
| 3c 预训练冻结 + 有增强 | **0.9500** | 0.9545 | 0.9500 | 0.9499 | 14.4 s |

**讨论**：
- 增强让从零训练的 resnet18 从 0.75 涨到 0.80（+5 个百分点），证明增强确实能提升泛化；
- 但与预训练叠加后（3c）准确率仍是 0.95，与不增强持平——**预训练已经很强时，增强的边际收益会变小**；
- 增强只作用于训练集，验证集必须保持干净的 Resize + Normalize，否则指标不可信。

### 第四步：torchvision 成熟模型横向对比

`scripts/step4_model_zoo.py` · 5 轮 · 均冻结骨干只训分类头

| 模型 | 准确率 | 精确率 | 召回率 | F1 | 参数量 | 体积 | 单图延迟 | 训练耗时 |
|---|---|---|---|---|---|---|---|---|
| resnet18 | 0.9500 | 0.9545 | 0.9500 | 0.9499 | 11,177,538 | 42.71 MB | 19.68 ms | 6.6 s |
| **mobilenet_v3_small** | 0.9500 | 0.9545 | 0.9500 | 0.9499 | **1,519,906** | **5.93 MB** | **13.14 ms** | **2.9 s** |
| shufflenet_v2_x1_0 | 0.8000 | 0.8571 | 0.8000 | 0.7917 | 1,255,654 | 4.96 MB | 18.00 ms | 3.3 s |

最佳模型（mobilenet_v3_small）在验证集上的混淆矩阵：

| 真实 \ 预测 | 猫 | 狗 |
|---|---|---|
| **猫** | 10 | 0 |
| **狗** | 1 | 9 |

**讨论**：三个模型准确率拉不开差距（0.80 ~ 0.95），此时**推理速度和模型体积才是选型关键**。
mobilenet_v3_small 与 resnet18 准确率完全打平，但体积只有它的 1/7、推理快 33%、训练快 2 倍，
是部署到手机 / 小程序的最优选择。这也正好为第六步部署做铺垫。

### 第五步：模型保存与单张图片推理

`scripts/step5_predict.py`

采用工程惯例：训练过程中**只保存验证集准确率最高的那一轮**（早停思想），
保存内容是 `state_dict` 加元信息（arch / classes / config / metrics），
因此一个 `.pth` 文件就是一份"可直接部署的模型"，推理端不必再猜网络结构。

```bash
python scripts/step5_predict.py --dir datasets --limit 12
# 抽查 12 张，正确 12 张，准确率 100.00%
```

### 第六步：封装成完整前后端应用

指导书用 Gradio"给模型套壳"，本实验升级为**前后端分离**架构：

- **后端** FastAPI：模型仓库、`/api/predict`（文件上传 / base64）、`/api/train`（后台训练 + 进度查询）、
  `/api/experiments`、`/api/dataset/stats` 等 11 个接口；
- **前端** 原生 HTML/CSS/JS（无框架、无 CDN、可离线）：识别 / 训练 / 实验对比 / 数据集四个页签，
  支持拖放上传、摄像头拍照、实时训练曲线、准确率条形图。

启动后访问 `http://127.0.0.1:8000`；加 `--lan` 后手机连同一 Wi-Fi 即可拍照测试。

## 四、总结

| 步骤 | 核心改动 | 实测准确率 | 核心结论 |
|---|---|---|---|
| 1. 手写 + 从零训练 | 随机权重 | 0.85 | 能学会，但慢且不稳 |
| 2. + ImageNet 预训练 | 冻结卷积只训分类头 | **0.95** | 迁移学习是小数据集最优解 |
| 2b. 全量微调 | lr=1e-5 解冻全部层 | 0.90 | 数据少时微调反而过拟合 |
| 3. + 数据增强 | 翻转/裁剪/色彩/旋转 | 0.80→0.95 | 提升泛化，且预训练够强时边际收益变小 |
| 4. 多模型对比 | resnet18 / mobilenet / shufflenet | 0.80~0.95 | 差距小时看体积与速度，mobilenet_v3_small 最优 |
| 5. 保存与推理 | state_dict + 元信息 | — | 训练与推理分离是工程标配 |
| 6. 部署应用 | FastAPI + 原生前端 | — | 模型只有被用起来才有价值 |

## 五、思考题

**1. 把冻结改为全模型微调（lr=1e-5），准确率和训练时间如何变化？**

实测：准确率 0.95 → 0.90（下降 5 个百分点），训练时间 10.0 s → 13.2 s（增加约 30%）。
原因是只有 80 张训练图，全量微调时 5700 万个参数都在这 80 张图上更新，
通用视觉特征被小数据"带偏"，属于典型过拟合；同时反向传播要贯穿整个网络，耗时自然上升。

**2. 把数据增强再加强（如 `RandomErasing`），观察置信度分布变化。**

思路：在 `src/catdog/data.py` 的 `build_train_transform` 里加入
`transforms.RandomErasing(p=0.3, scale=(0.02, 0.15))`。
预期是模型被迫不能再依赖"猫脸/狗脸"这类局部强特征，输出概率会更"保守"——
即高置信度（>95%）样本占比下降、概率分布更平滑，但准确率未必同步提升（增强过强反而会破坏语义）。

**3. 用 FastAPI 把 predict 封装成 HTTP 接口，写一个真正的微信小程序前端调用它。**

本项目已提供 `/api/predict` 接口，小程序端只需：

```js
wx.chooseImage({ success: (res) => {
  wx.uploadFile({
    url: 'https://your-domain/api/predict',
    filePath: res.tempFilePaths[0],
    name: 'file',
    success: (r) => {
      const data = JSON.parse(r.data);
      console.log(data.label_cn, data.confidence);   // "猫" 0.65
    }
  });
}});
```

后端一行都不用改——这正是前后端分离的价值：模型服务一次写好，Web / 小程序 / App 都能复用。
